# M1｜数据与确定性工具底座

里程碑目标：建立可重建的虚构数据、统一时间与单位口径，以及可独立验证的只读查询和统计工具。能力已实现；全系统最终验收见[M4](M4_质量验证与交付.md)。

## 交付与完成标准

- 固定JSON数据、SQLite schema、非覆盖式初始化与数据校验。
- query_health_data、query_medications及统一结果协议。
- 数值由工具确定性计算，身份由应用绑定，不允许模型传自由SQL。
- 最新记录、血压配对、空数据、单位拒绝、样本不足、事件冲突及跨患者隔离都有自动检查。

## 数据标识与范围

固定用户P001，由应用注入patient_id，模型不得覆盖。record_id为记录证据，measurement_id用于同次血压配对；medication_id标识一个剂量持续区间，event_id标识已确认的变更；report_id标识原文件，后续chunk_id标识片段。SQLite外键须在每个连接开启。

数据库结构以 `health_agent/schema.sql` 为准。schema版本为1，application_id为1212633428。源数据保存在JSON中；初始化只导入固定数据，不随机重采样。SQLite报告路径相对项目目录保存，迁移项目无需改绝对路径。

健康记录总数96：G001至G032为血糖，W001至W016为体重，SBP001/DBP001至SBP024/DBP024为24次血压。G031/G032时间相同但数值不同，作为同一时间两个不同来源记录的排序测试，不按时间单独去重；完整相同测量才视为疑似重复。该样例中的source字段标注统一数据集来源，record_id区分记录。

## 时间与查询边界

时间字符串统一为UTC的 `YYYY-MM-DDTHH:MM:SSZ`，本地日期转UTC后查询。区间统一左闭右开；自然语言“10月1日至15日”转换为本地[10月1日00:00，10月16日00:00)。最新记录为不晚于参考日本地结束时刻的记录，按measured_at DESC、record_id DESC稳定排序。未来记录不应成为“最近一次”。

药物start_date含当日，end_date为停用生效日且排除当日。查询当前用药：start_date ≤ reference_date，并且end_date为空或reference_date < end_date。事件的旧药end_date、新药start_date必须与event_date一致。

“去年”为[2025-01-01，2026-01-01)的报告日期范围；上传日期不得替代报告日期。“最近一个月”固定为含参考日在内的30个本地自然日，即[reference_date−29日00:00，reference_date＋1日00:00)。这条约定需同时在界面及回答中展示。

## 比较规则与检查顺序

先选择事件，再检查窗口内其他变更事件；有冲突则返回conflicting_events，不继续计算。默认14天，以事件日期D切为[D−14，D)与[D＋1，D＋15)，事件当天排除。若其他事件发生在同一事件日，也判定为冲突，避免只检查取样窗口而遗漏同日共同调整。

单位必须相同，血糖测量条件必须相同；未明确条件且范围内存在多类条件时，需要追问或分组展示，不能混合计算。unknown不推断成fasting。每窗至少3条，否则insufficient_data，不扩大窗口。默认窗口可显式调整为1至90的整数自然日；该上限是课程项目工程配置。

使用原始精度计算样本数、均值、最小值、最大值、差值及百分比，前均值为0时百分比为null并返回警告。使用Decimal从十进制字符串计算，最终按ROUND_HALF_UP展示：血糖、体重测量值1位小数，血压0位，百分比2位；汇总均值及绝对变化保留2位，避免7.95提前舍入影响变化计算。预期文件保存未提前舍入的均值。

E007无其他事件干扰，可作为稳定的描述性比较。E005的14天范围内存在E004和E006，必须返回冲突。E007缩为2天时仅有前2条后1条空腹记录，必须返回样本不足。

## 数据约束的两层校验

SQLite约束拒绝无效单位、未知指标、重复主键、无患者归属、错误用药区间及错误事件引用。初始化校验补充完整时间解析、血压配对、事件与用药边界一致性、文件哈希及重复测量检查。测试需要的坏输入在临时数据库或工具输入中构造，不污染主样例数据库。

## 开发接口

以下直接调用无需模型；工具层end_date是右开端点，自然语言截止日的规范化由Agent应用层完成。

### Python入口

```python
from health_agent.config import DEFAULT_DATABASE, load_config
from health_agent.results import ToolContext
from health_agent.tools import HealthTools

cfg = load_config()
context = ToolContext(cfg.patient_id, "demo-session", cfg.reference_date)
tools = HealthTools(DEFAULT_DATABASE, context=context, config=cfg)
result = tools.query_health_data({"indicator": "glucose", "mode": "latest"})
snapshot = tools.cache.get(result["result_id"], context=context, tool="query_health_data")
```

也可传入`HealthQuery`或`MedicationQuery`数据类。无论使用字典还是数据类，都经过相同的运行时参数校验；不使用隐式字符串转数字、布尔转整数等类型转换。

### query_health_data

| 参数 | 类型与默认值 | 约束 |
|---|---|---|
| indicator | 字符串，必填 | glucose、weight、systolic_blood_pressure、diastolic_blood_pressure、blood_pressure及已配置别名；血压整体别名支持“血压”“BP” |
| mode | latest | latest、series、summary、compare_event |
| start_date | 可空YYYY-MM-DD | 左闭；series和summary必须提供 |
| end_date | 可空YYYY-MM-DD | 右开；默认参考日次日；超过参考日结束会截断并返回warning |
| measurement_context | 可空字符串 | 血糖：fasting、postprandial、random、unknown；其他指标只接受unknown或不提供 |
| event_id | 可空字符串 | compare_event必须提供已由用药工具确认的事件ID |
| window_days | 默认14 | 仅compare_event可用，1至90的整数，拒绝布尔值 |
| requested_unit | 可空字符串 | 首版只支持标准单位；其他单位返回unsupported，不换算 |

latest返回最新单条记录；blood_pressure返回同次测量的两个分量和一个measurement对象。series按时间及record_id稳定排序。summary返回每个指标分量的描述性统计，血糖多条件时返回needs_clarification而非混合统计。

compare_event不能同时提供日期范围。先检查当前用户的事件，再检查同日及窗口内其他事件；有冲突返回conflicting_events。之后读取两个窗口的同类记录，每个指标分量每窗至少3条，且完整后窗必须已经结束。条件混杂返回needs_clarification；样本不足或窗口未结束返回insufficient_data且delta为null。已成功返回的比较仅描述时间关联。

日期、UTC窗口和具体记录在data中保留。统计值mean、sum、min、max、delta和percent_change使用Decimal计算后保存为十进制字符串；display为展示字符串，均值及差值2位、百分比2位。前均值为0时百分比为null，返回zero_baseline警告。空窗统计为null而不是0。

### query_medications

| 参数 | 类型与默认值 | 约束 |
|---|---|---|
| mode | current | current、history、events |
| medication_name | 可空字符串 | 药名精确匹配，ASCII不区分大小写；作为SQL绑定值，不拼接SQL |
| start_date / end_date | 可空YYYY-MM-DD | 左闭右开；current禁止提供，历史查询使用history |
| event_id | 可空字符串 | 仅events可用 |
| event_type | 可空字符串 | 仅events可用：start、stop、switch、dose_change |

current按参考日期判断，并按medication_id稳定排序；停用生效日不包含在旧药区间。history返回与查询区间相交的用药记录，按start_date、medication_id排序。events返回时间范围内事件、事件关联的旧药与新药；药名筛选同时检查事件两侧，候选项不由工具自动选择。

### 公共返回格式

```json
{
  "status": "ok",
  "result_id": "res_<unique-id>",
  "data": {},
  "evidence": [],
  "warnings": [],
  "error": null
}
```

status枚举：ok、no_data、needs_clarification、insufficient_data、conflicting_events、unsupported、error。error存在时包含code和message。evidence按记录或事件包含source_type、source_id、locator及原始记录快照；没有证据不生成虚构来源。

健康证据包含record_id、单位、测量时间和条件；用药证据包含medication_id、剂量、频率及生效区间；比较同时返回事件证据和样本记录证据。

### 命令行退出状态

health和medications命令的工具status为error时退出码1；ok及可处理业务状态（如no_data、unsupported、insufficient_data）退出码0，调用方必须读取JSON里的status。无效JSON返回ok=false并退出码1。init与validate保持安全初始化及数据校验行为。

## 快照缓存与维护入口

直接构造HealthTools默认使用进程内ResultCache；聊天应用工厂使用SQLiteResultCache，支持跨实例读取有效快照。两者默认30分钟，按患者、会话、参考日期及工具隔离；持久缓存还绑定数据库命名空间。绘图使用快照的边界见[M3](M3_RAG与可视化.md)。

实现入口：`health_agent/schema.sql`、`seed.py`、`contracts.py`、`statistics.py`、`tools.py`、`cache.py`。数据源为`sample_data/seed.json`与四份登记TXT。当前主库不因文档整理而重建。

## 双语拼写与数值

中英文显示和单位拼写规范化不改变数值、患者、时间、记录ID或统计结果。kg/kilograms/公斤可作同一单位标签；pounds不能当kg，micrograms不能当milligrams。首版不做单位换算。英文日期的自然语言终日也按包含式规范化为工具右开端点；解释和界面必须与实际工具范围一致。
